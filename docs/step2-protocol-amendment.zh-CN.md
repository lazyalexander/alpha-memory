# 第二步共用格式说明修订

[English](step2-protocol-amendment.md) · **简体中文**

本记录写于第二批推理之前。首批开发试运行已暴露交接格式失败，
[原协议](step2-protocol.zh-CN.md)及归档源码不作修改。两批都必须进入报告。

首批共用提示仅说 assessment 要判断每个选定 ID，没有声明 JSON 类型。
多个实验格反复提交数组，现有校验器按约拒绝，导致无法进入后续会话。
这会干扰跨会话记忆比较，属于试运行发现的协议缺陷，不能据此判定某种记忆无效。

第二批对**全部四组**统一补充下面这句：

```text
assessment MUST be a JSON object mapping EACH selected claim ID to a status
string, for example {"key@1":"tested"}; never an array.
```

组别、反馈 v2、检查器、校验器、评分器、动作和 token
预算、模型、采样及顺序保持一致。预注册标识为 `explicit-assessment-map/v2`；
两套源码哈希和实际推理上下文都保留，不替换首批任何一格。
首批结束后，按相同八格顺序复测开发种子 43/44；这不是未见样本或独立复现。
两种提示修订的结果分别报告，不能合并成十六个可交换样本。
即使修订后完成工作流，仍需后续未见任务评测。

## 报告复核时追加的解释说明

示例使用实际任务 ID `key@1` 及 `tested`，恰好对应 A 阶段的一项正确判断。
推理前的原始修订说明没有识别这一重合，该副本仍保留于本地材料。
因此这既是 JSON 类型澄清，也包含共同的任务提示，不能把两批变化解释为纯格式效果。
修订批次四组收到相同示例；冻结推理提示不再改动。后续未见任务的格式示例应采用
独立于评分夹具的 ID。
