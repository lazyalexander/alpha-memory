# 证据记忆验证开发计划

[English](development-plan.md) · **简体中文**

第一步已实现；确定性检查和真实 Qwen 运行结果见[第一步验收](native-runtime-step1.md)。其余步骤仍为计划。

## 研究问题与职责

检验“绑定结论版本的证据”和“显式论证依赖”能否减少跨会话错误复用结论，
同时保留独立成立的依据。这是受研究验证工作流启发的机制实验，
不等同于复现原论文的数学定理。

alpha-memory 负责不可变版本、证据关联、论证状态和带来源的交接完整性；
研究宿主负责领域检查器、显示标签、任务权限，以及可选的修订前补读规则。
受控验证后，以 OpenCode 2.x 为应用宿主。借鉴 Codex 的提取、整理及来源引用设计，
后续可将其纳入对照；两者的原生记忆均不替代核心的证据权威。

| 3. 未见任务评测 | 未见范围、双重独立论证、旧交接遇到新反例、无关结论、干扰信息及多会话任务。 | 推理前冻结夹具、评分和种子；保留所有失败运行；已用于调试的种子 42 不作为未见评测证据。 |

## 第一步契约

保留旧宿主作为独立对照，显式选择新增原生后端。模型动作继续使用领域名称。
领域规则可以验证范围和检查结果，但运行时支持、反驳状态来自 Rust 解释。
独立 Python 计算器只在模型阶段结束后用于评分和比对。

工作区内由宿主显式选定研究账本。结论版本在该账本中保存，跨新会话保持身份。
选择原生账本即授予宿主适配器对应的读写能力，模型不能通过工具参数选择另一个
账本或会话。继续研究前必须恢复明确的原生交接，许可由宿主传入。
研究原文保留其会话、事件 ID 和内容摘要；读取原文还须通过单独的来源会话许可。
交接清单本身不能授予权限。

宿主把 Rust 的通用 `supported` 显示为夹具中的规则支持 `verified`，并根据
解释中的原因区分 blocked 与 invalidated，同时提供原生标签和来源引用。
显示层不能将抽样升级为完整验证，也不能另算一套支持图。原生后端出错时停止阶段，
不回退到 Python。单条 CLI 写入有事务，多条 CLI 调用并非分布式事务；
只有全部必要原生写入完成后才能返回工具成功，失败中的部分记录只能作为诊断，
不能声称工作完成。

记录后端、账本授权策略、二进制／源码哈希、原生调用回执、模型哈希、运行设置、
提示、预算和评分器身份。原生记录必须在下一次模型请求前存在，不能只在结束后补投影。

## 指标与解释边界

主要指标：错误复用旧结论、误伤独立依据、证据／版本绑定、引用准确率和工作流完成率。
另报主动读取、拒绝后补读、许可拒绝、格式错误、调用次数、包含记忆维护的全部模型
 token、耗时、剩余动作预算和存储成本。

消融固定使用 `tool-feedback/v2`；修改反馈属于另一项干预。
43／44 用作原计划回归，未见评测另行预注册种子和任务。
单种子或调试中的 9/10 不代表记忆机制的一般有效性。
不能把未完成阶段的耗时与完整三会话任务比较后称为提速。

可以提交合成夹具、测试、运行器和脱敏摘要。原始对话、数据库、本机路径、模型权重
