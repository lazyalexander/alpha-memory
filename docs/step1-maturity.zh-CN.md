# 第一步成熟度与验收成果

[English](step1-maturity.md) · **简体中文**

**当前成熟度：可重复验收的研究原型。第一步工程门槛通过，可以进入受控消融；
原十项研究任务尚未全通过，论文有效性和生产成熟度均未成立。**

本轮在已有原生运行路径上继续开发，重点补齐失败处理、独立复放和可重复验收。
不是把先前的单次 9/10 重新描述为稳定系统。

## 本轮开发成果

- 原生 CLI 调用设置 30 秒截止；非零退出、程序缺失、超时、无效 JSON 和响应结构错误
  都形成致命后端错误，写入诊断并停止当前模型阶段。没有自动切换 Python 的路径。
- CLI 回执记录单次耗时和错误类型。模型工具成功只在所需原生调用完成后返回。
- 审计器增加空库复放：使用固定二进制重放每条原生调用，比较 Rust 计算出的实际响应，
  不只比较彼此一致的 JSON 日志。复放只接受已知操作和参数，不接受日志指定工作区。
- 新增无需模型的一条命令验收。每轮从空工作区启动“修订”和“旧交接遇到新反例”两种
  场景，各由三个独立进程执行，传递显式交接引用和来源许可。
- 故障测试直接走阶段循环，验证失败后没有第二次模型请求；重开数据库确认未承认结论写入。
  另用临时慢程序验证真实 subprocess 超时，不只模拟 TimeoutExpired。

该开发失败不计作后来规范验收的通过，也不从过程记录中删除。

确定性验收入口位于研究仓库：

```sh
python3 bench/native_acceptance.py run \
  --binary /path/to/alpha-memory \
  --rounds 3 --output bench/runs/step1-acceptance
```

脚本动作期间关闭 Python 支持状态计算，阶段结束后才用独立计算器核对。
这些是工程夹具，不是模型评分。

## 模型表现与成本

模型为桌面已有的 Qwen3-30B-A3B-Instruct-2507 Q8_0；固定权重摘要、非思考模式、
温度 0.6、top-p 0.95、每次 1,024 token 上限、反馈 v2 和 10/12/14 步预算。
原十项评分器没有修改。43、44 是开发回归，不是未见任务实验。

| 种子 | 会话完成 | 原评分 | 模型调用 | 工具错误 | 模型调用耗时 | 运行器总耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| 42，上一版原生冒烟 | 3/3 | 9/10 | 30 | 3 | 135.41 秒 | 当时未测量 |
| 43，本轮 | 3/3 | 9/10 | 26 | 2 | 101.38 秒 | 115.11 秒 |
| 44，本轮 | 3/3 | 9/10 | 31 | 6 | 187.33 秒 | 202.03 秒 |

运行器总耗时包含该轮预检、模型文件摘要和宿主调用，不包含服务启动和结束后的审计。
本轮原生 CLI 时间合计约 0.53／0.73 秒，调用 64／66 次；它不包含其他宿主工作。
两轮实际越权读取拒绝均为 0；模型工具错误和后端故障分别计数。

三个种子的失分均是：模型先调用完整检查器，再使用其揭示的反例，
没有满足“在检查器揭示前独立提出反例”。因此运行器按原评分规则退出码为 1，
不代表进程崩溃；阶段失败字段均为空。不能把 9/10 当成十项全通过。

42 的原生宿主版本与本轮加固版本不同。本轮有限检查算法未变，但超时管线修改使
所在模块的检查器摘要变化。源码和检查器身份分别记录；这些结果不作为单变量消融或
统计成功率。模型观察中有宿主计算的状态，评分也不代表无辅助推理能力。

[模型回归明细](../bench/step1-model-regression.json)保留所有十项评分、阶段错误、补读、预算、
成本和审计检查。原始对话、回执及数据库留在忽略目录，临时模型服务已关闭。

历史审计也覆盖了仅检查器模块变化的情况：旧运行使用归档源码复核，
归档损坏时拒绝执行。42、43、44 均完成了本轮最终审计复查。

## 成熟度边界与下一步

现在可以依靠该研究宿主开展受控实验，并用明确的失败信号排查问题。
仍仅支持每项研究一个显式可写账本；没有一般化的多账本合并、跨库原子提交、
崩溃后自动续写、长时间并发运行或跨宿主版本检查器兼容性验收。
研究宿主远端尚未配置，代码在本地 dev；核心 dev 上有计划、接口和脱敏报告。

下一步进入计划中的四组消融，冻结本轮反馈、权限和评分规则；
然后使用另行预注册的未见任务、种子和完整成本指标。
在这些证据完成前，对外结论应限于“第一步工程链路及重复验收通过”。
